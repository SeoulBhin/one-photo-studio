# one-photo-studio — 한 장 스튜디오

제품 사진 한 장으로 3D 모양을 만들고, 원하는 앵글·조명으로 돌려 PNG 로 저장하는 내 PC 용 웹 도구.
마지막엔 이 캡처를 참조로 붙여 내 PC 의 Codex CLI 가 연출 컷(광고 사진)을 만들게 하는 게 목표다. 지금은 1단계.

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 병처럼 축 대칭인 제품: 사진 → 외곽선(자동 + 손으로 고치기) → 돌려 만든 3D → 덧입히기(부위별 재질·색, 라벨, 받침·배경지) → 앵글·조명 → PNG | 됨 |
| 2 | 상자(패키지 박스) 모양, OBJ 저장 | 예정 |
| 3 | 앱에서 Codex CLI 로 연출 컷(외부 API 키 없음, 내 PC 의 로그인 기반 CLI) | 됨(12편, 2단계보다 먼저) |

## 실행

```bash
$ npm install
$ npm run build
$ python serve.py
한 장 스튜디오: http://127.0.0.1:8411
```

화면은 [Astryx](https://www.npmjs.com/package/@astryxdesign/core) 디자인 시스템(React, stone 테마, canvas-editor 템플릿의 틀)으로 만들었다. 글꼴만 한글이 되는 Pretendard 로 바꿔 앱 안에 넣어서 실행 중 외부 요청은 0건이다. 파이썬 표준 라이브러리 서버가 빌드 결과(`dist/`)를 `127.0.0.1` 에만 열고, 다른 호스트 이름으로 온 요청은 403 으로 막는다.

3단계에서 이 서버에 Codex 를 부르는 요청(POST)을 붙일 땐 Origin 확인과 실행마다 바뀌는 토큰도 함께 건다. 다른 웹페이지가 내 PC 의 Codex 를 돌리지 못하게 하려는 것.

## 쓰는 법

1. 사진을 끌어다 놓거나 예시(갈색 앰플·흰 로션병)를 누른다. 배경이 단색에 가깝고 정면에서 찍은 사진이 잘 된다
2. 왼쪽에 외곽선 점이 뜬다. 어긋난 곳은 점을 끌어서 고친다. 선 위 더블클릭 = 점 추가, 점 우클릭 = 삭제, 점선(축) 끌기 = 축 이동
3. 가운데 3D 를 드래그해서 앵글을 잡는다. 휠로 가까이·멀리
4. 겉면: 몸통·뚜껑을 따로 고른다. 재질은 사진·유리·무광·유광·금속, 색은 견본 8개나 직접 고르기. 뚜껑 경계는 자동으로 잡히고, 사진 위 빨간 선을 끌어 옮긴다
5. 라벨: 예시 라벨이나 내 이미지를 몸통에 감는다. 높이·크기·감는 각도 조절
6. 세트: 배경지 색 5가지, 받침(원기둥·대리석·아크릴). 앵글은 정면·45°·내려다보기 프리셋 또는 마우스
7. 조명: 원판은 위에서 본 세트(아래쪽이 정면). 노란 점이 빛이 오는 쪽, 가운데로 갈수록 머리 위. 프리셋 넷(왼쪽 위·옆에서·역광·머리 위)
8. 크기를 고르고 PNG 저장. 화면 비율(4:5)과 저장 비율이 같아서 보이는 구도 그대로 저장된다

## 연출 컷

오른쪽 아래 "연출 컷"에서 장면을 고르고(석회암 자연광, 대리석 스튜디오, 물결 수면, 리넨과 그림자, 먹색 무드) 설명을 고친 뒤 [연출 컷 만들기]를 누르면, 지금 앵글·조명으로 뜬 1080×1350 캡처를 로컬 서버가 내 PC 의 Codex CLI 에 넘긴다. 1분 남짓 뒤 가운데가 "3D 캡처 | 연출 컷" 비교 보기로 바뀌고 [연출 컷 저장]으로 받는다. 결과와 캡처, Codex 기록은 `out/shots/<작업>/` 에 남는다(저장소엔 안 올림).

- Codex 는 `codex exec --ignore-user-config -s read-only -c features.experimental_windows_sandbox=true -c features.elevated_windows_sandbox=true --json - -i capture.png` 로, 저장소 밖 임시 폴더에서 부른다. 내 설정 파일을 안 읽어 MCP 연결이 빠지고, 읽기 전용 + 윈도 샌드박스라 파일을 쓰거나 명령을 실행하지 못한다(진짜 Codex 로 "파일을 써 봐라"를 시켜 막히는 것 확인). 그림 생성만 한다
- 프롬프트는 명령줄이 아니라 표준입력으로 넘긴다(윈도의 codex.CMD 는 인자가 cmd.exe 를 거쳐 `&`, `|`, `%` 가 해석될 수 있다)
- 결과는 Codex 의 생성 폴더 중 이번 작업 번호(`thread_id`) 폴더에서만 찾는다. 따로 돌린 다른 Codex 작업의 그림을 집지 않는다
- 이 요청은 Host·Origin·JSON·실행마다 바뀌는 토큰(이 앱 페이지에만 끼워 줌) 네 가지를 다 맞춰야 받는다. 다른 웹페이지가 내 PC 의 Codex 를 돌리지 못하게 하려는 것. 한 번에 하나, 5분 제한, 취소 가능, 결과 조회에도 토큰. 다만 같은 PC 에서 도는 다른 프로그램(브라우저 밖)은 첫 페이지를 받아 토큰을 얻을 수 있다 — 혼자 쓰는 내 PC 시연용이라 받아들인 한계

## 외곽선을 따는 방법

`src/outline.js`(DOM 없는 순수 함수)

1. 줄마다 왼쪽·오른쪽 가장자리 색으로 그 줄의 배경색을 잡는다(위아래 그라데이션 배경 대응)
2. 배경과 확실히 다른 픽셀에서 시작해, 조금이라도 다른 픽셀로 번져 가며 가장 큰 덩어리를 제품으로 본다. 흰 병처럼 배경과 차이가 14 정도인 몸통도 잡히게 하려는 것
3. 그렇게 넓게 잡으면 바닥 그림자도 붙는다. 그래서 줄마다 바깥에서 안쪽으로 훑어 색이 뚝 끊기는 선명한 경계가 처음 나오는 곳을 가장자리로 본다. 그림자는 가장자리가 흐려서 빠진다
4. 줄 폭의 절반 = 반지름, 줄 가운데의 중앙값 = 축. 꺾이는 곳(어깨·뚜껑 턱)이 살도록 점을 24개 이하로 줄인다

3D 겉면은 사진을 정면에서 그대로 투영한다. 뒷면은 앞면과 같은 그림을 받는다. 사진 속 음영이 그대로 남아서, 조명을 크게 바꿀 땐 단색이 더 자연스럽다.

## 시험

```bash
$ node --test tests/outline.test.mjs   # 합성 이미지 12건: 반지름·턱·흰 병·그림자·라벨·얼룩·튀는 줄·실패·3D 점 목록·뚜껑 경계
$ python -m unittest tests/test_server.py tests/test_shot.py # 연출 컷 서버 8건 + 작업 관리 1건(가짜 Codex): 막아야 할 요청 10종, 특수 문자, 인자, 다른 폴더 그림 무시, 409·취소, 실패 문구
$ npm run build && python tests/e2e.py # 헤드리스 크로미움 60항목(연출 컷은 가짜 Codex): 예시 2장으로 사진→편집(끌기·추가·삭제·축)→덧입히기→조명→저장, 실패 처리, 외부 요청 0건
```

e2e 가 저장한 PNG 는 `out/` 에 남는다(눈으로 확인용, 저장소엔 안 올림).
